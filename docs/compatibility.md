# 兼容范围与已知限制

当前面向 Windows x64 便携版，版本见 package.json。我们已对大量 Windows 应用进行测试；应用版本、权限及具体输入控件仍会影响适配结果。

系统依赖包括 .NET Framework 4.8、可用的图形驱动和 Microsoft Visual C++ v14 x64 运行库。Neovim 的可执行文件实际依赖 `VCRUNTIME140.dll`，发布包未复制系统 DLL；缺少时请使用[微软官方下载](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist?view=msvc-170)。

| 项目 | 状态 |
| --- | --- |
| 原生编辑与中文增强 | 当前 Neovim 自动回归通过；包含英文差分、拼音查找、跨行计数、寄存器、重复动作及草稿合同 |
| Microsoft To Do | 用户已确认同一输入框回填问题修复，日志与复测一致 |
| Windows 任务栏搜索 | 已知不可自动回填；提交复制到剪贴板，需要重新打开搜索框后手动粘贴 |
| 微信（复测版本 4.1.13.65） | 已知不可自动回填：未得到可确认的焦点输入控件；提交复制到剪贴板，需要切回输入框手动粘贴 |
| 其他已测试应用与输入控件 | 可确认原输入框时尝试一次回填；无法确认时使用剪贴板回退 |
| 真实输入法组合、多屏 DPI、权限差异 | 尚未形成完整桌面验收矩阵 |
| 原剪贴板恢复 | 未实现；提交文字继续保留在剪贴板 |

目标识别只读取控件能力、窗口/进程身份和焦点信息，不读取目标正文；诊断记录进程名、控件类型和结果，不记录目标文字。提交前复验原控件身份，窗口变化、目标失效、超时或按键未释放时取消粘贴。最多发送一次 Ctrl+V，不发送 Enter、不全选、不自动重试。

“已发送粘贴”只确认按键发送，不证明目标应用已经接收文字。开启“系统通知”时，每次成功复制的非空提交均请求结果通知，包含未知目标和非输入位置；该开关位于 F2 → 编辑与草稿，默认关闭、立即生效并保存。升级保留已保存的选择。关闭后不发系统通知，复制、粘贴及草稿保存照常执行。Windows 禁用通知时无法保证通知可见。草稿在失败时保留。

便携包使用可写目录中的 prototype-profile。升级先保存需要的草稿、退出旧实例，再迁移设置/草稿，不迁移进程记录。托盘退出清空按用户设置执行。
